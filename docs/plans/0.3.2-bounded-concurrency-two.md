# PawnLogic 0.3.2 Bounded Concurrency Two Plan

> **Status:** Release finalization staged. `v0.3.1` is published; the 0.3.2
> tag, PyPI publication, and GitHub Release remain pending separate
> authorization.

## Goal

Allow a supported Delegation Runtime batch caller to run at most two independent
child tasks concurrently without sharing mutable RuntimeContext, workspace,
stdout, cancellation, budget, or Tool-execution state.

## Delivered Design

- `SerialAgentOrchestrator` accepts only one or two synchronous workers. It
  keeps FIFO admission and input-order results, gives every admitted task a
  child cancellation token, and settles atomic shared-budget claims exactly
  once.
- A two-worker `DelegationTaskExecutor` requires a forkable parent
  `RuntimeContext`; accidental use without one fails closed. The executor also
  rejects accidental parallel calls unless the orchestrator configured it for
  two workers.
- Each task forks a copied RuntimeContext and a unique directory below
  `<parent-workspace>/.tasks/`. Its dynamic configuration, output collector,
  stdout capture, and cancellation token are task-local. Isolated contexts do
  not mirror legacy process globals.
- Relative child work uses the child workspace. Concurrent mode allows only
  task-isolated file Tools; network, shell, container, extension, MCP, and
  other non-isolated Tool paths are denied before their handler executes.
- Task-token cancellation closes only that task's provider connection. Global
  interrupts fan out to active streams, while a child cancellation does not
  cancel a sibling or its parent.
- Child Tool/usage events are captured locally and forwarded through a
  thread-safe publisher. Worker terminal output is bounded and never directly
  interleaves on the parent stdout stream.

## Acceptance Gates

- Two concurrent tasks prove independent cwd, workspace, dynamic config,
  relative file round-trips, output, and structural events.
- Shared budgets, queued/running deadlines, host cancellation, and task-only
  cancellation retain their defined outcomes with zero lingering reservation.
- A two-worker Delegation Runtime without a forkable parent context fails
  before task start; a non-isolated Tool is denied before its handler runs.
- `tools/check_architecture_budget.py`, docs/index guards, ruff, typed-island
  mypy, staged leak scans, and `git diff --check` pass.
- Release finalization is verified independently from 0.3.1 release gates. No
  tag or publication is created by this plan.

## Explicit Non-Goals

- No task graph, automatic planning fan-out, UI batch command, or implicit
  parallelism for `delegate_task`.
- No permission to make shell, network, container, MCP, extension, browser,
  pwn, or sandbox Tools concurrent. Those need separate isolation designs.
- No forced termination of an uncooperative synchronous handler; deadlines and
  cancellation remain cooperative at the current handler boundaries.
- No automatic cleanup policy for successful task workspaces. Retention and
  cleanup need a separately authorized UX/data-retention decision.
