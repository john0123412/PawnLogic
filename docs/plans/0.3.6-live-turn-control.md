# PawnLogic 0.3.6 Live Turn Control Plan

> **Status:** Active. Implementation and release evidence will be recorded here
> before the plan is marked complete.
>
> **Version note:** This cycle is 0.3.6 per the AGENT.md Version Numbering
> Policy: the minor (second) digit never moves without an explicit owner
> decision, so the live-turn-control scope ships as a patch release.

## Goal

Give the REPL mainstream live turn control: input stays available while a Turn
runs, mid-turn Enter steers at the next safe point, follow-up messages queue
for natural completion, and interruption becomes per-Turn and side-effect safe.
Today the REPL reads no input during a Turn; Ctrl+C is the only input path and
the MessageQueue mixes future work, pending work, and Ctrl+C retry in one
deque, silently drops messages when full, and shares one process-level
interrupt event.

## Interaction Contract

| Scenario | Behavior |
|---|---|
| Idle + Enter | Start a new Turn immediately. |
| Running + Enter | Submit a steer; it takes effect at the next safe point. |
| Running + Alt+Enter | Submit a follow-up; it runs after the current Turn finishes naturally. |
| Running + Esc | Interrupt the current Turn; composer draft and queues are preserved. |
| Alt+Up | Recall the most recent queued message into the editor. |
| /queue | Open the queue TUI distinguishing steer, follow-up, and recovered entries. |
| /queue remove \<id\> | Remove one queued message. |
| /queue clear | Clear queued messages only. |
| /abort | Interrupt the active Turn only (semantics change; docs migrate in the same cycle). |
| /abort --all | Interrupt the active Turn and clear all queues. |
| Restart / resume | Restore conversation and queues; an unfinished Turn becomes an editable draft. Side-effect Tools are never replayed automatically. |

Steer safe point: after the current Tool Call completes. Tool calls from the
same batch that have not started yet are recorded as structured
`skipped` results so the protocol stays complete; their plan-guard accounting
follows ADR 0009. The steer is appended as a new user message and the model is
requested again. A streaming text-only response is not torn apart; Esc remains
the immediate-interrupt path.

Guarantees: context, queued input, and completed tool results are never lost,
and side-effect tools are never replayed without confirmation. No guarantee of
resuming from the middle of an arbitrary syscall or network request.

## Phases

### P0 - Product Contract (this phase)

- This plan, ADR 0009, and the CONTEXT.md vocabulary below.
- A terminal E2E RED baseline proving that input sent during a running Turn is
  not consumed until the Turn ends (strict xfail until the scheduler lands).

Gate: owner reviews the contract and ADR before any P1 implementation.

### P1 - TurnScheduler

- New deep module `core/turn_scheduler.py` replacing (not wrapping)
  `core/message_queue.py`.
- Three-entry interface: `submit(submission)`, `control(action)`,
  `view()`. Stable submission IDs, strict FIFO, explicit error instead of
  silent drop when full. The unused `priority` field and the module-level
  singleton are removed.
- State machine: IDLE, RUNNING, STEER_QUEUED, FOLLOW_UP_QUEUED, RECOVERABLE.
- Production executor Adapter wraps `AgentSession._run_turn_active()`; tests
  use an in-memory Adapter. CLI, remote control, and tests share one Interface.
- Acceptance: pure state-machine tests with no sleeps (concurrency tests use
  Event/barrier); `core/session.py` net line count decreases (budget is
  2100 and current headroom is near zero).

### P2a - Always-available input

- Prompt Toolkit composer stays on the main thread and remains active during
  Turns; output returns through patch_stdout / the Output Sink.
- Ctrl+C is handled as a key binding that calls `control()` and triggers
  cooperative cancellation. Python signal handlers may not interrupt the
  worker thread; the per-Turn CancellationToken from the delegation runtime
  pattern is the only cancellation mechanism.
- Acceptance: typing during a long tool execution works with zero output
  corruption and bounded Ctrl+C latency.

### P2b - Execution in a worker thread

- Turn execution moves to a worker thread through the TurnExecutor Adapter.
- Before implementation, an audit lands for module-level globals
  (`_user_mode`, `_debug_mode`, `_dynamic_config`) and RuntimeContext legacy
  mirrors: each is either encapsulated behind RuntimeContext or documented as
  thread-confined.
- Interactive tools (pwn_debugger and similar) are verified not to compete
  with the composer for tty stdin.
- The readline fallback stays serial with an explicit notice that live input
  requires Prompt Toolkit.
- Gate: owner sees a live demo of typing during a long tool execution.

### P3 - Steer and follow-up

- The steering queue is checked at Tool-call safe points; remaining batch
  tools get `skipped` results.
- Follow-ups are consumed only after natural stop, one per Turn, so distinct
  intents never merge into one user message.

### P4 - Interruption redefinition

- Global interrupt event replaced by per-Turn cancellation tokens.
- Esc and Ctrl+C trigger the same Turn control. `/abort` interrupts the active
  Turn only; `/queue clear` handles queued messages; `/abort --all` does both.
- An interrupt fully closes unfinished Tool Call protocol pairs.
- README (English and Chinese), the recovery hint, and any 0.3.5 references to
  the old `/abort` semantics migrate in the same commit series.

### P5 - Persistence and restart recovery

- Scheduler snapshots carry a schema version; every enqueue, edit, remove,
  claim, finish, and interrupt writes an atomic checkpoint.
- Old `queue_state` migrates: queued becomes follow-up, pending becomes a
  recovered draft.
- Restart never auto-replays pending side-effect Tools. Add
  `pawn --continue` and `pawn resume <session>`.

### P6 - Queue TUI

- Stable sequence numbers, type, content summary, and status; recall, remove,
  clear, and type conversion.
- Bottom toolbar shows `Running · steer: N · follow-up: N`.

### Deferred

- Cross-process control (`pawn queue --session ...`) requires a Unix socket /
  app-server layer and is deferred past 0.3.6.

## Acceptance Gates

- Input and editing work during long tool executions; output stays aligned.
- Steer takes effect at a safe point; follow-ups run only after natural
  completion; multiple messages stay independent, unmerged, unduplicated, and
  never silently dropped.
- After Esc the composer, queues, and context recover; repeated
  interrupt/retry cycles never replay tool side effects.
- Forced process exit restores queues without auto-replaying the active Tool.
- Pure state-machine tests do not sleep; concurrency tests use Event/barrier.
- Real terminal E2E on Linux/WSL2 and at least one real provider smoke pass.
- Ruff, typed-island mypy, documentation structure, language policy, release
  consistency, architecture budget, and code index pass; the Python
  3.10/3.11/3.12 matrix, package build, fresh-install smoke, Dynamic E2E, and
  remote Actions pass before publish.
- `/abort` documentation shows no mixed old/new semantics.

## Non-Goals

- No Provider behavior or retry-policy changes.
- No changes to the delegation runtime concurrency model.
- No plan-guard semantic changes beyond the steer accounting interface.
- No cross-process control in this cycle.
