# PawnLogic 0.3.7 Inline Terminal Stability Plan

> **Status:** Active. The implementation and the GREEN evidence for this
> plan have not landed yet. The 0.3.6 doc cleanup that this plan depends
> on is committed on `rebuild/inline-terminal-0.3.7` (commit
> `8cbb1d3`); the plan file and ADR 0010 are committed on top.
>
> **Version note:** This cycle is 0.3.7 per the AGENT.md Version
> Numbering Policy: the minor (second) digit never moves without an
> explicit owner decision, so the inline-terminal and selector-modal
> scope ships as a patch release.

## Goal

Stabilize the live terminal by restoring native terminal scrollback,
mouse selection, and copy-paste, and unify the interactive selector
experience under a single Prompt Toolkit `Application` dialog state.
Today the persistent terminal enters the alternate screen buffer and
owns the mouse, so the user's native terminal cannot scroll, select, or
copy the live transcript. The `/model`, `/planguard`, `/provider`, and
`/skills` selectors all rely on a fragile "exit main `Application` ->
restore stdout -> run selector -> rebuild main `Application`" handoff
that breaks the persistent transcript, the queue preview, and the
toolbar.

## Scope

- Run the live composer without `full_screen=True` so the user's
  terminal keeps its own scrollback and native mouse selection. The
  persistent transcript moves to a `TerminalTranscript` buffer that
  flushes to the host terminal output through the same `Output` sink
  the readline fallback already uses.
- Run the live composer without `mouse_support=True` so wheel events
  flow to the host terminal first; coordinate-aware terminal
  capabilities are still routed to the output viewport when the
  terminal advertises them.
- Replace `LiveTerminalController.pause_for_modal` and its
  `resume_after_modal` pair with an in-`Application` dialog state. The
  same modal framework hosts `/model`, `/planguard`, `/provider`,
  `/skills`, and any future interactive selector; the main
  `Application` never tears down.
- Record the new constraints in
  [ADR 0010](../adr/0010-inline-terminal-modal.md).
- Keep the readline fallback serial and unchanged: the in-`Application`
  dialog state is gated on Prompt Toolkit being available and active.

## Acceptance Gates

- A PTY smoke test proves a long transcript is selectable with the host
  terminal's mouse and scrollable with the host terminal's wheel after
  the live composer is up.
- A PTY smoke test proves the output viewport still receives
  coordinate-aware scroll events when the terminal advertises them,
  while the host terminal keeps the default for everything else.
- An integration test proves `/model` opens the selector without exiting
  the main `Application`, selecting a model returns control to the live
  composer, and the queue preview, the toolbar, and the
  recovered-draft marker all survive the round trip.
- The same modal framework is reused by `/planguard`, `/provider`, and
  `/skills`; each one round-trips without rebuilding the main
  `Application`.
- Live composition key bindings (`Enter`, `Alt+Enter`, `Esc`, `Ctrl+C`,
  `Ctrl+Z`, `Alt+Up`) still behave exactly as documented in the 0.3.6
  plan.
- Readline fallback remains serial; the in-`Application` modal path is
  not reached when Prompt Toolkit is unavailable or
  `PROMPT_TOOLKIT_ENABLED=0`.
- Relevant tests, E2E, ruff, typed-island mypy, documentation checks,
  release consistency, architecture budget, code-index freshness, and
  `git diff --check` pass.
- A release candidate later passes the Python 3.10/3.11/3.12 matrix,
  package build, fresh-install smoke, Dynamic E2E, and remote Actions
  before publish.

## Explicit Non-Goals

- No version bump, tag, PyPI upload, GitHub Release, or remote branch
  operation in the implementation step.
- No change to the live turn control contract from 0.3.6; the Enter /
  Alt+Enter / Esc / queue / recovery behaviors remain exactly as
  shipped.
- No change to the provider runtime, the tool registry, or the
  delegation orchestrator; the inline-terminal work is strictly UI
  plumbing.
- No change to the readline fallback, to `DANGEROUS_PATTERNS`, or to
  Operation / Network / Trust policies.
- No cleanup or merge of stale local branches without separate
  authorization.

## Risks

- Prompt Toolkit and the host terminal share the same input stream;
  turning the alternate screen off may expose previously hidden PT key
  sequences to the host shell. The bounded escape-sequence window from
  0.3.6 and the new `TerminalTranscript` buffer are the mitigations;
  real-input PTY smoke tests must keep them covered.
- The in-`Application` dialog state must not block the live Turn or
  steal input from the composer. Modal lifecycle, focus restoration,
  and per-frame layout must be deterministic; the persistent TUI's
  existing tests are the regression baseline.
- The single-`Application` selector must tolerate selectors that
  long-jump to another selector (e.g. `/model` from inside the provider
  TUI); the modal stack must be explicit and bounded.

### Phase B — interactive selectors (DONE, code-complete; release prep still pending)

The four interactive selectors that still owned their own PT
`Application` and were slated to be ported to
`controller.run_selector` are now all routed through the controller
when one is attached to the `CommandContext`:

1. `/model` — `cc_style_model_selector` in
   `core/commands/provider.py:733`. **DONE** — runs through
   `controller.run_selector` when a controller is attached.
2. `/planguard` — `_select_plan_guard_mode` in
   `core/commands/system.py:441`. **DONE** — runs through
   `controller.run_selector`; the E2E test
   `test_slash_planguard_tui_applies_selected_mode` flipped back to
   green. The auto-correct notice now reaches the host PTY via
   `controller.bypass_print` so the user sees it before the selector
   renders.
3. `/provider` — `run_provider_tui` in `core/provider_tui.py:1170`
   invoked from `cmd_provider` in
   `core/commands/provider.py:880`. **DONE** — runs through
   `controller.run_selector`. `_handle_provider_cmd` now accepts a
   `terminal_controller` keyword and routes the TUI through it.
4. `/skills` — interactive TUI invoked from `cmd_skills` in
   `core/commands/tools.py:445`. **DONE** — runs through
   `controller.run_selector`; `cmd_skills` now routes the TUI
   through the controller when present.

Each port:

- Schedules the selector through `controller.run_selector`, so the
  main `Application` task identity is preserved across the round
  trip and `Application.exit()` is not called on the main app.
- Adds a contract test in `tests/test_model_selector_modal.py`
  (`test_planguard_dispatch_uses_run_selector_when_controller_is_present`,
  `test_model_dispatch_uses_run_selector_when_controller_is_present`,
  `test_provider_dispatch_uses_run_selector_when_controller_is_present`,
  `test_skills_dispatch_uses_run_selector_when_controller_is_present`)
  that exercises the dispatch path with a stub controller.
- Falls back to the original independent-`Application` path when
  no controller is attached, so readline-only sessions and tests
  keep working.

**Caveat — selector Application identity.** Each selector still
launches its own Prompt Toolkit `Application` (the in-Application
Float overlay rewrite that would make the selector literally share
the main `Application` is out of scope for 0.3.7). What the
`run_selector` plumbing **does** guarantee today is that the
**main** `Application` is not torn down, its task identity is
preserved, and the main `Application`'s `exit()` is never called as
part of a modal round trip. The ADR-0010 single-Application
dialog-state rewrite remains an architectural follow-up.
