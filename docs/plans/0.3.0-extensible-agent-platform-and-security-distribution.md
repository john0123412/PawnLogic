# PawnLogic 0.3.0 Extensible Agent Platform And Security Distribution Plan

> **Status:** Active. PR 1 opened as
> [#79](https://github.com/john0123412/PawnLogic/pull/79) on 2026-07-26.
>
> **For agentic workers:** Implement this plan in small, reviewable vertical
> slices. Characterize current behavior before moving it. Never mark a remote,
> package-publishing, or release step complete without recording the relevant
> run, artifact, or release URL.

**Goal:** Turn PawnLogic into an extensible agent host while keeping the core
`pawnlogic` distribution small and compatibility-preserving. Deliver
network-security and penetration-testing capabilities as a separately
versioned PyPI distribution that PawnLogic can discover automatically, enable
explicitly, invoke through slash commands, and expose to authorized Agent Turns.
Deepen delegated-agent model routing so a parent Agent can provide focused
instructions and request another eligible model under user-owned policy.

**Architecture:** Introduce a deep Extension Runtime Module at a stable Seam.
Installed distributions advertise Extension metadata through Python package
entry points; enabled Extensions contribute validated Tool Specs, slash
commands, prompt fragments, and optional runtime Adapters. The proposed
`pawnlogic-security` distribution remains outside the core wheel and uses an
Engagement Scope plus the shared Operation Policy before active network work.
Deepen the current synchronous `delegate_task` implementation into a Delegation
Runtime that owns prompt composition, model routing, context selection, budgets,
tool capability filtering, and structured results. Follow-on work deepens
Context, Knowledge Retrieval, Agent Event, and UI Modules without replacing
stable public Provider, stream, message, Tool Call, or persistence contracts.

**Tech Stack:** Python 3.10+, setuptools, `importlib.metadata`, PyPI entry
points, SQLite/FTS5, optional Redis Stack, stdio MCP, prompt_toolkit, Rich,
optional Streamlit, pytest, Ruff, selective mypy, build, twine, and GitHub
Trusted Publishing.

## Executive Decision Record

1. The security feature set will not be added directly to the core
   `pawnlogic` wheel.
2. The proposed distribution name is `pawnlogic-security`; the import package
   is `pawnlogic_security`. The final public name must be checked before the
   first publishing PR.
3. Core Extension discovery will use package metadata entry points under the
   provisional group `pawnlogic.extensions`.
4. Discovery is read-only and does not import Extension code. Loading and
   registration occur only after explicit enablement.
5. Installing an Extension does not enable it. Security tools are hidden from
   the model until the Extension is enabled and a valid Engagement Scope is
   active.
6. The security distribution also exposes an independent console command,
   provisionally `pawn-security`, so it can operate and be tested without the
   PawnLogic REPL.
7. Entry points provide discovery and contribution metadata. High-risk or
   dependency-heavy execution may use a stdio MCP Adapter or a dedicated child
   process so the core process does not import the entire security toolchain.
8. The current `delegate_task` Tool Call will remain compatible, but its
   implementation will move behind a Delegation Runtime Interface.
9. Parent Agents may provide focused subagent instructions and a model
   requirement or Model Alias. The host, not the model, makes the final routing
   decision using user-configured allowlists, cost limits, Provider visibility,
   capabilities, and availability.
10. SQLite remains the durable source of truth for local memory in this
    iteration. Redis is optional retrieval/index infrastructure, not the sole
    durable store.
11. Streamlit remains an optional separately installable Adapter over a stable
    Agent Event Interface. It does not become a dependency of the core package.

## Global Constraints

- Keep `config/paths.py:VERSION` at `0.2.3` until release preparation.
- Preserve `pawn`, `python main.py`, `python -m pawnlogic`, and `./pawn.sh`.
- Preserve DeepSeek's always-active rule and custom Providers' inactive
  default.
- Preserve current model visibility rules across `/model`, completions,
  Provider commands, the Provider TUI, and delegated-agent routing.
- Preserve public stream delta dictionaries, assistant/tool message shapes,
  Tool Call ordering, and `reasoning_content` persistence.
- Preserve the `ToolRegistry` invariant: no Tool Spec is visible without an
  executable handler.
- Preserve default user-friendly output and `pawn --debug` behavior.
- Do not auto-install Python packages, browser runtimes, scanners, system
  packages, containers, or MCP servers from an Agent Turn.
- Do not auto-enable newly discovered Extensions.
- Do not allow a prompt fragment, Skill Pack, Extension, or subagent instruction
  to override host safety policy.
- Do not run active network assessment without explicit Engagement Scope,
  authorization, and bounded budgets.
- Do not include third-party Skill Packs in core or security wheels without the
  required redistribution review.
- Do not make Redis, Streamlit, Docker, browser, or security dependencies
  mandatory for a normal `pip install pawnlogic`.
- Use temporary `PAWNLOGIC_HOME` for all tests and smoke runs.
- Do not push, merge, publish, tag, or release without explicit maintainer
  authorization for that phase.

## Audited Baseline

### Core Packaging

- `pyproject.toml` defines one distribution, `pawnlogic`, and one console
  command, `pawn`.
- Core package discovery includes `pawnlogic*`, `config*`, `core*`, `tools*`,
  and `utils*`.
- Source-checkout Skill Packs are explicitly excluded from wheels and sdists.
- There is no Python entry-point group for external PawnLogic Extensions.
- Optional extras install dependencies but cannot conditionally remove files
  from a wheel.

### Tool Registration

- `core/tool_registry.py` already provides the correct Registry Seam:
  handler, schema, phase, trust kind, and capabilities are registered together.
- Built-in Tool handlers are imported and registered from `core/session.py`.
- MCP Tools are the second existing Adapter at the Registry Seam.
- Extension discovery, lifecycle, enablement state, compatibility checks, and
  command contributions do not exist.
- `AGENT_PHASES` is a mutable process-global route table. MCP currently appends
  discovered Tools to it at runtime.

### Delegated Agents

- `tools/delegate_tool.py` runs a lightweight synchronous subagent with a fresh
  message list and real Tool side effects.
- Automatic worker routing uses the current model when it is fast, otherwise a
  configured preferred worker, a same-Provider fast peer, or the fixed fallback
  order `ds-v4-flash`, `claude-haiku`, `gpt-4.1`.
- `/worker <alias>` accepts any registered Model Alias, but the displayed
  candidate menu is fixed and the setting is process-local.
- The public Tool schema intentionally omits `model_alias`, so the parent model
  cannot currently request a particular eligible model.
- Subagent prompt composition is fixed in code. The parent can provide only the
  task description, capability profile, and verbosity.
- The subagent receives at most five persistent facts, not a structured slice
  of the parent Turn.
- Delegation is synchronous, has a hard 15-iteration cap, and has no separate
  token, cost, Provider-call, or wall-clock budget contract.
- The subagent sees a capability-filtered Registry snapshot rather than the
  parent Turn's phase-filtered Tool set.

### Context And Memory

- Main Turns use a first-turn anchor, a model-generated history summary, and a
  sliding window.
- Hard character compaction uses `ctx_max_chars`; the configured `ctx_trim_to`
  target is not applied by the current compaction implementation.
- Summaries are prose and do not preserve a typed task state.
- Knowledge search uses SQLite `LIKE` filtering and keyword-hit scoring.
- Conversation history uses SQLite FTS5 with a `LIKE` fallback.
- Agent facts use key/value rows and keyword scoring.
- GSA experience retrieval uses Markdown blocks, Jaccard title similarity,
  hit/confidence metadata, and FSRS-style time decay.
- There is no embedding pipeline, vector index, reranker, Redis Adapter,
  provenance-aware retrieval record, or durable indexing outbox.

### User Interfaces And Automation

- `HumanSink` and `JsonSink` are the current output Adapters.
- `JsonSink` emits NDJSON events, but there is no stable domain-level Agent
  Event contract.
- There is no Streamlit, FastAPI, Gradio, or WebSocket UI.
- There is no general Extension command namespace.
- MCP servers can be configured and loaded, but MCP is not a package discovery
  or enablement interface.

## Confirmed Architecture Friction

### 1. Import-Time Tool Assembly Is Not An Extension Interface

**Files:** `core/session.py`, `core/tool_registry.py`,
`core/mcp_client_manager.py`, `config/phases.py`.

**Problem:** Built-in imports, optional dependency handling, Registry mutation,
and phase mutation are concentrated in `core/session.py`. A separately
distributed package has no supported way to contribute Tools or commands.

**Deepening:** Add an Extension Runtime Module whose small Interface owns
discovery, compatibility validation, enablement, contribution loading,
registration, rollback, status, and shutdown.

**Leverage:** Built-in, Python package, MCP-backed, and test Extensions use one
Interface.

**Locality:** Extension failure handling and compatibility checks stop leaking
into startup, session construction, command modules, and package-specific code.

### 2. `delegate_task` Has A Small Schema But A Leaky Runtime Contract

**Files:** `tools/delegate_tool.py`, `core/session.py`, `core/state.py`,
`config/providers.py`, `core/commands/tools.py`.

**Problem:** Model selection, prompt construction, context inheritance, Tool
filtering, execution, output capture, budgets, and status are implemented in
one Tool handler. Callers cannot request role-specific instructions or another
eligible model, while tests must know internal routing details.

**Deepening:** Add a Delegation Runtime Module with a structured `AgentTask`
input and `AgentResult` output. Keep `delegate_task` as an Adapter.

**Leverage:** CLI commands, the parent Agent, future orchestration, and UI all
delegate through the same Interface.

**Locality:** Prompt safety, Model Alias eligibility, budget enforcement, and
context selection become one test surface.

### 3. Network Policy Is Distributed Across Tool Implementations

**Files:** `core/operation_policy.py`, `core/trust.py`, `tools/web_ops.py`,
`tools/browser_ops.py`, `tools/docker_sandbox.py`,
`core/mcp_client_manager.py`.

**Problem:** URL validation, private-network notices, redirects, network
enablement, and subprocess policy are implemented at several call sites. A
security Extension would multiply this drift.

**Deepening:** Introduce one Network Policy Module that evaluates normalized
Network Operations and returns explicit allow, confirm, or deny decisions.

**Leverage:** Built-in web, browser, MCP, Docker, and security Adapters use one
policy Interface.

**Locality:** SSRF, redirect, DNS, IP-range, port, rate, and Engagement Scope
rules are fixed and tested once.

### 4. Context Compression And Delegation Context Are Separate Policies

**Files:** `core/session.py`, `core/context_window.py`,
`core/prompt_builder.py`, `tools/delegate_tool.py`.

**Problem:** Main Turn sliding windows, hard compaction, summary generation,
prompt assembly, and subagent inheritance are separate paths. Task decisions,
artifacts, failed attempts, and open questions can disappear into prose.

**Deepening:** Add a Context Manager Module that produces a typed
`ContextEnvelope` for both main and delegated Turns.

**Leverage:** Provider calls, delegated agents, JSON automation, and UI consume
one context result.

**Locality:** Character budgets, structured summaries, retrieval injection, and
message repair become one Interface.

### 5. Local Knowledge Has Multiple Retrieval Algorithms But No Retrieval Seam

**Files:** `core/memory.py`, `core/gsa.py`, `core/persistence.py`,
`core/prompt_builder.py`.

**Problem:** SQLite FTS, SQL keyword scoring, fact search, and GSA scoring expose
different result shapes and provenance. Adding Redis directly to these callers
would create a second set of branching logic.

**Deepening:** Add a Knowledge Retrieval Module that owns durable records,
indexing state, query planning, keyword/vector Adapters, reranking, provenance,
and fallback.

**Leverage:** Prompt construction, `/knowledge`, delegated agents, security
workflows, and UI query one Interface.

**Locality:** Redis availability, embedding versions, score normalization, and
fallback behavior remain internal.

### 6. Output Sinks Are Not Yet A UI Event Interface

**Files:** `core/output.py`, `core/runtime_context.py`, `pawnlogic/cli.py`,
`core/session.py`.

**Problem:** Human text and NDJSON serialization exist, but Tool lifecycle,
retrieval evidence, agent hierarchy, budgets, and Turn completion are not
represented by a stable event shape.

**Deepening:** Add an Agent Event Module; make terminal, NDJSON, and future
Streamlit renderers Adapters.

**Leverage:** One Turn implementation serves CLI, automation, tests, and UI.

**Locality:** Rendering and transport changes stop affecting Agent execution.

## Proposed Core Interfaces

These shapes are design targets, not final code signatures. The implementing
PR must add contract tests before freezing public names.

### Extension Runtime

```python
@dataclass(frozen=True)
class DiscoveredExtension:
    name: str
    distribution: str
    version: str
    entry_point: str

@dataclass(frozen=True)
class ExtensionMetadata:
    name: str
    version: str
    core_version_spec: str
    description: str
    trust: TrustBoundaryKind
    capabilities: frozenset[str]

@dataclass(frozen=True)
class ExtensionContribution:
    tools: tuple[ToolSpec, ...] = ()
    commands: tuple[CommandSpec, ...] = ()
    prompt_fragments: tuple[PromptFragment, ...] = ()
    phases: tuple[PhaseContribution, ...] = ()

class ExtensionRuntime:
    def discover(self) -> tuple[DiscoveredExtension, ...]
    def enable(self, name: str) -> ExtensionStatus
    def disable(self, name: str) -> ExtensionStatus
    def status(self, name: str | None = None) -> tuple[ExtensionStatus, ...]
    def shutdown(self) -> None
```

Invariants:

- `discover()` reads entry-point and distribution metadata without importing
  Extension code. Full `ExtensionMetadata` is loaded and validated only during
  explicit enablement.
- Enablement is explicit and persisted under Runtime Home without secrets.
- Contributions are validated as one transaction before Registry mutation.
- Name collisions fail closed; no silent overwrite.
- Failed enablement rolls back Tool, command, phase, and prompt contributions.
- Disabling removes only contributions owned by that Extension.
- Extension startup and shutdown are idempotent.
- Core startup remains successful when an Extension is incompatible or broken.

### Delegation Runtime

```python
@dataclass(frozen=True)
class AgentTask:
    objective: str
    role: str = "general"
    instructions: str = ""
    model_requirement: str = "auto"
    model_alias: str | None = None
    context_mode: str = "selected"
    capability_profile: str = "inherited"
    allowed_tools: tuple[str, ...] = ()
    budget: AgentBudget = AgentBudget()

@dataclass(frozen=True)
class AgentResult:
    status: str
    summary: str
    model_alias: str
    artifacts: tuple[ArtifactRef, ...]
    evidence: tuple[EvidenceRef, ...]
    failures: tuple[FailureRecord, ...]
    usage: AgentUsage

class DelegationRuntime:
    def run(self, task: AgentTask, parent: RuntimeContext) -> AgentResult
```

Invariants:

- Host system instructions and safety policy are always prepended and cannot be
  replaced by `AgentTask.instructions`.
- A requested Model Alias must be visible, configured, allowed by user policy,
  compatible with the requested capability, and within budget.
- Rejected model requests fall back predictably or fail with an explicit
  routing reason.
- `context_mode` selects references; it never copies secrets or unbounded parent
  history.
- Tool visibility is the intersection of phase, Extension enablement,
  capability profile, explicit allowlist, and policy decisions.
- Nested delegation remains disabled until RuntimeContext isolation and budget
  accounting are proven under concurrency.

### Network Policy

```python
@dataclass(frozen=True)
class NetworkOperation:
    tool_name: str
    scheme: str
    host: str
    port: int | None
    resolved_ips: tuple[str, ...]
    redirect_chain: tuple[str, ...]
    method: str
    active_probe: bool

class NetworkPolicy:
    def authorize(
        self,
        operation: NetworkOperation,
        scope: EngagementScope | None,
    ) -> OperationDecision
```

The implementation must cover DNS resolution changes, redirect targets,
loopback, link-local, private networks, cloud metadata addresses, IPv4/IPv6,
port ranges, rate budgets, active-versus-passive behavior, and non-interactive
fail-closed behavior.

### Knowledge Retrieval

```python
@dataclass(frozen=True)
class KnowledgeQuery:
    text: str
    namespaces: tuple[str, ...]
    top_k: int
    max_chars: int

@dataclass(frozen=True)
class RetrievalHit:
    record_id: str
    source_type: str
    source_id: str
    content: str
    score: float
    score_kind: str

class KnowledgeRetriever:
```

SQLite remains authoritative. Redis may store vector/index projections with

### Engagement Scope

Every active network-security workflow must receive a validated Engagement
Scope containing:

- authorized domains, IPs, CIDRs, and ports
- excluded targets
- authorization reference or user acknowledgement
- allowed passive and active actions
- destructive actions, disabled by default
- maximum requests, concurrency, and wall-clock duration
- evidence directory
- expiry time

Security Tools must fail closed when scope is absent, expired, ambiguous, or
does not contain the resolved target. Redirects and DNS changes are rechecked
against scope at execution time.

### Initial Security Capability Set

The first independently released package should prioritize safe, bounded,
evidence-producing workflows:

1. Scope validation and target normalization.
2. Passive DNS, TLS, HTTP-header, and technology reconnaissance.
3. Bounded port and service discovery within explicit scope.
4. HTTP request replay with redaction and rate limits.
5. Local evidence capture and reproducible run manifests.
6. Scanner Adapter integration only when the binary is already installed and
   explicitly enabled.
7. Exploit or destructive workflows only in later releases with separate
   policy gates, container isolation, and maintainer review.

The package must not silently download scanner binaries, wordlists, browser
runtimes, containers, or system packages.

## Subagent Prompt And Multi-Model Design

The revised `delegate_task` Tool schema should let the parent Agent express why
another model is useful without granting unbounded model selection:

```json
{
  "objective": "Review the authentication flow for SSRF risks",
  "role": "security-reviewer",
  "instructions": "Focus on redirect and DNS rebinding behavior.",
  "model_requirement": "reasoning",
  "model_alias": "claude-sonnet",
  "context_mode": "selected",
  "capability": "read_only"
}
```

Routing order:

1. Validate an explicit `model_alias` against visible models and user policy.
2. Otherwise match `model_requirement` to model capabilities.
3. Prefer a same-Provider eligible peer when policy requests it.
4. Apply user-defined preferred worker and allowlist.
5. Apply maximum-cost, maximum-token, and Provider-call budgets.
6. Fall back to the current model only when it is eligible.
7. Return the selected Model Alias and routing reason in `AgentResult`.

User controls:

```text
/agent policy show
/agent policy model allow <alias>
/agent policy model deny <alias>
/agent policy default auto|same|fast|reasoning
/agent policy max-cost <amount>
/agent policy max-concurrency <n>
/agent run <role> <objective>
```

The existing `/worker` command remains as a compatibility Adapter and maps to
the default delegated-agent model policy.

Parallel multi-agent execution is deferred until:

- RuntimeContext and Output Sink state are isolated per agent
- Workspace writes have explicit ownership
- Tool side effects are serialized or conflict-checked
- budgets are atomic
- cancellation and child-process cleanup are proven

When enabled, the initial concurrency default is one and the hard maximum is
two. A task graph and shared blackboard should not be added until structured
`AgentTask` and `AgentResult` contracts have shipped and stabilized.

## Context, RAG, Redis, JSON, And Experience Accumulation

### Context Manager Plan

- Apply both `ctx_max_chars` and `ctx_trim_to`.
- Count content, reasoning, Tool arguments, and retained Tool results.
- Preserve the first task anchor, recent Turns, pinned messages, and structured
  task state.
- Produce a `ContextEnvelope` with goal, constraints, facts, decisions,
  artifacts, failed attempts, open questions, current phase, and next actions.
- Let delegated agents receive references selected by policy instead of raw
  parent history.
- Add summary-version metadata so old summaries can be regenerated.

### Knowledge Retrieval Plan

- Keep SQLite as durable storage for messages, knowledge, facts, failures, and
  source metadata.
- Add normalized knowledge records and chunk records with stable IDs.
- Add an indexing outbox so Redis/vector indexing can resume after failure.
- Add a keyword Adapter using SQLite FTS/LIKE.
- Add an optional Redis vector Adapter.
- Fuse and normalize scores before reranking.
- Preserve source, source revision, retrieval algorithm, embedding model,
  index version, and score in every hit.
- Fall back to keyword retrieval when Redis is absent, stale, or unavailable.
- Never inject unlimited retrieved content; enforce Top-K and character budgets.

### Experience Accumulation

Successful Turns may produce a candidate Experience Record containing:

- problem fingerprint
- verified solution
- evidence and artifacts
- failed approaches
- applicable constraints
- confidence
- source session and Tool Calls

Automatic extraction creates a candidate only. Promotion to durable reusable
experience requires deterministic verification evidence or user confirmation.
Repeated failures remain separate from successful experience and keep their
current audit role.

### JSON Distinction

- JSON and NDJSON are serialization formats for Tool arguments, configuration,
  events, and automation output.
- RAG is a retrieval process over durable knowledge records and indexes.
- Redis is an optional index/cache Adapter.
- SQLite is the durable source of truth in this plan.
- An Agent Event serialized as JSON does not become a Knowledge Record unless a
  deliberate ingestion rule promotes it.

## Release And Compatibility Policy

- Core 0.3.x follows semantic compatibility for the Extension contracts.
- Security releases are independently versioned, initially 0.1.x.
- The Extension declares a supported core version specifier and refuses
  incompatible enablement with a clear message.
- Core does not import or depend on `pawnlogic_security`.
- Security may depend on a compatible core release for shared contracts.
- Deprecations require at least one documented core minor release before
  removal.
- Entry-point names, Tool names, command names, event schema versions, and
  AgentTask/AgentResult versions are explicit compatibility surfaces.
- Production publication of either distribution requires its own green CI,
  TestPyPI smoke, Trusted Publisher configuration, changelog, and release notes.

## Stop Conditions

Stop the affected PR and request maintainer direction when:

- the proposed public PyPI name is unavailable or conflicts with another
  project
- an Extension must import private core globals to function
- rollback cannot restore Registry, command, phase, and prompt state atomically
- an active network operation cannot be proven inside Engagement Scope
- a Tool path bypasses Operation Policy or Network Policy
- delegated agents can select an unconfigured, inactive, denied, or
  over-budget Model Alias
- concurrent agents can race on Workspace paths, output sinks, runtime config,
  persistence, or Tool side effects
- Redis becomes required for core startup or local knowledge retrieval
- Streamlit work requires terminal-output parsing or direct mutation of
  `AgentSession` internals
- wheel inspection finds security code or third-party Skill Pack content in the
  core distribution

## Success Criteria

The plan is complete when:

- `pawnlogic` remains fully usable with no optional Extensions installed.
- `pawnlogic-security` is independently installable, testable, versioned, and
  publishable.
- PawnLogic discovers the installed security Extension without importing it,
  keeps it disabled by default, and enables it explicitly through commands.
- Security Tools are visible only when enabled and validly scoped.
- Direct `pawn-security` execution and PawnLogic-hosted execution share the
  same security workflow Interface.
- A parent Agent can supply focused subagent instructions and request another
  eligible model under user-owned routing and budget policy.
- Delegated-agent results are structured, attributable, bounded, and observable.
- Context compression preserves structured task state and applies configured
  targets.
- Local RAG keeps SQLite durable storage, supports optional Redis vector
  retrieval, and always has a bounded keyword fallback.
- CLI, NDJSON, and optional Streamlit Adapters consume stable Agent Events.
- Core and optional distributions pass independent packaging and release gates.
